# Contributing

## Prerequisites

- The .NET SDK pinned in [`global.json`](../global.json) (10.0.103, rolling forward to the latest feature band).
- SQL Server, only if you want to run the Blogs sample.

## Build and test

```bash
dotnet build                                  # whole solution
dotnet test                                   # all test projects
dotnet test test/RootBlocks.Tests/            # one project
dotnet pack src/RootBlocks/RootBlocks.csproj --configuration Release
```

| Test project | Covers |
|--------------|--------|
| `test/RootBlocks.Tests` | Extension methods, `ValidationResult`, `Retry` |
| `test/RootBlocks.Serialization.Tests` | `DomainEventConverter<T>` |
| `test/RootBlocks.AspNetCore.OpenApi.Tests` | `JsonPatchExampleTransformer`, against a real generated document |

## Repository layout

```
src/        one folder per NuGet package
test/       xUnit test projects
samples/    the Blogs reference application
docs/       this documentation
```

## Coding conventions

- Group class members with `#region` blocks: Fields, Properties, Constructors, Interface Implementations, Overrides, Operators, Public Methods, Private Methods.
- Put global `using` directives in each project's `Usings.cs`.
- Use the spaced style used throughout the code: `Method( arg )`, `List< T >`, `[ Attribute ]`. `.editorconfig` and `RootBlocks.slnx.DotSettings` hold the formatting rules.
- All datetimes are UTC.
- Entity IDs are assigned by the domain, never generated by the database.
- `Enumeration` values are `public static readonly` fields on the subclass.
- Only add an extension method when the BCL does not already provide it.
- Do not add identifier types or anything built around them (converters, EF conversions, OpenAPI transformers). They belong in [StronglyTypedIdentifier](https://github.com/sebdesalvador/StronglyTypedIdentifier).
- Each OpenAPI transformer gets its own named `OpenApiOptions` extension method. Do not add an umbrella method.
- Public APIs in newer code carry XML doc comments. Follow the style of `Retry`, `ValidationResult` and the extension classes.

## Versioning

Versions come from git tags through [MinVer](https://github.com/adamralph/minver). Tags are prefixed with `v` (for example `v0.5.0`). There is no version number in any `.csproj`. A commit after a tag gets a pre-release version such as `0.5.1-alpha.0.3`.

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `refactor!:`, ...). A `!` or a `BREAKING CHANGE:` footer marks a breaking change.

## Continuous integration and releases

The [`publish`](../.github/workflows/publish.yml) workflow runs on every pull request, every push to `main`, and every published GitHub Release:

1. **create_nuget** packs every package in a matrix and uploads each `.nupkg` as an artifact.
2. **run_test** runs `dotnet test --configuration Release`.
3. **deploy** runs **only when a GitHub Release is published**. It pushes every package to nuget.org with `--skip-duplicate`.

To release, tag the commit (`v1.2.3`) and publish a GitHub Release from that tag. Publishing the release uploads the packages to nuget.org, and that upload cannot be undone (packages can only be unlisted).

When you add a new package, add it to the matrix in `publish.yml`, to `RootBlocks.slnx`, to the package table in the [README](../README.md), and to [Target frameworks](target-frameworks.md).
